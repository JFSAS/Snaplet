# Snaplet 分阶段实现计划

更新时间：2026-10-06。

目标：使用 Swift + AppKit 实现本机 iShot 的主要使用流程，逐阶段交付可运行版本；通过实测优化响应、内存和能耗。当前参考是本机 iShot 2.6.5 的设置和界面，不承诺尚未核对的所有隐藏功能已进入清单。

## 实施规则

- 每阶段交付一个可运行版本，并记录代码状态、自动检查、真实操作结果和剩余问题。
- “代码已实现”“编译通过”“实际使用验证通过”分别记录。阶段功能必须经过真实流程验证才能标记完成。
- 快捷键沿用本机 iShot 设置；只注册已实现功能的快捷键，避免无效入口。
- 在当前功能稳定后进入下一阶段。需要硬件、权限或外部服务的验收明确记录条件。
- 应用代码先保持 Swift；只有测量证明需要时才引入其他语言或第三方依赖。
- 每阶段形成 Git 提交；需要时增加修复提交。未经真实验证的代码不称为稳定发布。

这些值来自本机 `cn.better365.ishot` 的 `dicOfShortCutKey` 设置；区域截图还通过 iShot 设置界面确认。Snaplet 目前只实现并注册区域截图。

| 延时截图 | ⌥D | 阶段 4 |
| 带壳截图 | ⌥R | 阶段 4 |
| 剪贴板贴图 | ⌥S | 阶段 3 |
| 隐藏/显示全部贴图 | ⌥H | 阶段 3 |
| 打开贴图库 | ⌥F | 阶段 3 |

| 翻译 | ⌥T | 阶段 5 |

## 当前检查结果

- Debug 应用构建和本地签名通过。
- 4 项自动测试通过：截图坐标原点转换、全屏/上边缘坐标、PNG 尺寸及像素颜色往返、快捷键解析和序列化。
- 真实界面检查：基础窗口、截图入口、权限提示、快捷键录入、取消录入、自定义组合键与默认组合键显示。
- 最新启动界面显示区域截图快捷键为 ⌥A，注册过程没有报告错误。
- 待验收：在其他应用前台按实体键触发截图；授权后的框选与采集；预览/复制/保存的完整桌面流程；多显示器和 Retina；重复截图后的资源释放。
- 未测量 iShot 与 Snaplet 的 CPU、内存、延迟或能耗差异，不宣称性能已超过 iShot。

## 性能比较方法

在同一台 Mac、同一组显示器、相同分辨率、相同功能与操作条件下记录：待机内存和 CPU、快捷键到框选显示的延迟、截图到预览的延迟、大图编辑峰值内存、关闭预览后的回落、重复截图后的增长，以及录屏的帧率、掉帧、CPU 和能耗。明确测量工具与样本次数，分开列出应用进程和相关辅助进程，不仅比较安装包体积。
