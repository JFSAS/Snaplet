# 故障记录

## 2026-10-06：开启屏幕录制权限后仍提示未授权

### 复现与证据

点击“开始区域截图”，出现“Snaplet 需要屏幕录制权限”。系统设置中 Snaplet 开关已开启；重启同一路径的应用后仍可复现。

通过只读查询 Snaplet 自己的系统授权记录，确认屏幕采集授权值为允许，但对应的代码要求是旧可执行文件的 `cdhash`。当前应用的 ad-hoc 指定要求绑定另一个 `cdhash`，旧授权不满足当前应用身份。

### 原因与修复

打包脚本每次使用 ad-hoc 签名，默认应用身份随编译产物变化。授权后的代码重新构建，导致系统设置中的旧授权不能用于新构建。

构建脚本现在支持 `SNAPLET_SIGNING_IDENTITY` 或本地 `.signing-identity`，使用已安装的开发证书签名并检查签名。当前机器已配置已有的本地开发证书，没有安装证书或修改钥匙串信任。未配置证书的机器仍可用 ad-hoc 构建，但脚本明确提示权限可能随构建失效。

只重置 `dev.snaplet.app` 的 ScreenCapture 授权后重新授权，使记录绑定开发证书身份。没有修改 TCC 数据库或其他应用授权。

同时修正首次授权处理：若 `CGRequestScreenCaptureAccess()` 返回成功，可以继续进入框选，不再无条件显示权限帮助。

### 验证

- `swift test`：4 项测试通过。
- `scripts/check-signing.sh`：两个内容不同、代码哈希不同的 Swift 可执行文件具有相同的开发指定要求，第二个文件通过第一个文件的代码要求验证。
- 原始操作复查：点击“开始区域截图”进入框选，未再显示权限提示。
- 实际界面已出现 956 × 307 px 的截图预览，说明 ScreenCaptureKit 采集成功。
- 本轮没有完成复制后粘贴、保存后读回、多显示器、重复截图内存的全面验收；这些仍属于阶段 1 的后续检查。

### 预防

从阶段 1 开始配置稳定开发签名，并把身份稳定性检查加入修改构建脚本时的验证。不要通过不断重置权限掩盖应用身份变化，也不要为 ad-hoc 构建指定仅匹配 bundle ID 的宽松代码要求。
